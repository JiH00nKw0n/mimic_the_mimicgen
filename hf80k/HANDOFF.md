# FR3 큐브 쌓기 데이터 생성 파이프라인 실행 안내

이 문서 하나만 보고 처음부터 끝까지 실행할 수 있게 적었다. 시뮬레이터에서 FR3 로봇이 큐브
세 개를 탑으로 쌓는 장면을 만들고, 카메라 세 대로 찍고, LeRobot 데이터셋 형식으로 바꿔
허깅페이스에 올리는 일을 컨테이너 하나가 끝까지 한다.

## 1. 받는 것과 놓는 위치

두 개를 받는다. 하나는 코드 폴더 `hf80k`이고, 다른 하나는 자산 묶음
`hf80k_assets.tar.gz`(62 MB)다. 자산은 용량이 커서 코드에 넣지 않았으므로, 압축을 풀어
코드 폴더 안으로 옮겨야 한다.

코드 폴더를 원하는 곳에 두고 아래처럼 자산을 넣는다. 아래 예시는 코드 폴더를
`/home/ubuntu/mimic_the_mimicgen/hf80k`에 둔 경우다.

```bash
tar xzf hf80k_assets.tar.gz
mv hf80k_assets/fwd_annotated.hdf5 \
   hf80k_assets/fr3_cube_system_calibration_bundle_v1 \
   hf80k_assets/fr3_visual_randomization_v1 \
   /home/ubuntu/mimic_the_mimicgen/hf80k/assets/
```

옮기고 나면 이런 모양이 된다. 앞으로 나오는 명령은 전부 `hf80k` 폴더 안에서 실행한다.

```
/home/ubuntu/mimic_the_mimicgen/
  hf80k/                     이 폴더 안에서 make를 실행한다
    Makefile                 실행 명령이 전부 여기 있다
    .env.example             설정 본보기. 이걸 복사해 .env를 만든다
    docker/Dockerfile        도커 이미지를 굽는 정의 파일
    src/                     파이프라인 코드
    assets/                  방금 옮긴 자산 세 개가 여기 있어야 한다
      fwd_annotated.hdf5                      사람이 조종해 녹화한 시연 13개
      fr3_cube_system_calibration_bundle_v1/  실물에서 잰 물리값
      fr3_visual_randomization_v1/            조명과 색과 카메라 규격
    README.md                더 자세한 설명
    INTERFACE.md             환경변수와 파일 형식의 규격서
```

도커 이미지 정의 파일의 전체 경로는
`/home/ubuntu/mimic_the_mimicgen/hf80k/docker/Dockerfile`이다. 다만 이 파일을 직접
`docker build`로 부를 필요는 없다. 빌드에 필요한 경로와 옵션을 `make build`가 이미 알고
있다.

## 2. 필요한 환경

NVIDIA GPU가 달린 리눅스 기계에 도커가 설치돼 있고, 컨테이너가 GPU를 쓸 수 있어야 한다.
`docker run --rm --gpus all nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi`가 GPU 목록을
출력하면 준비된 것이다.

디스크는 두 군데가 필요하다. 도커 이미지가 설치되는 곳에 약 60 GB가 있어야 한다. 이미지
자체가 51 GB이고 빌드 도중에 여유가 더 필요하다. 그리고 결과가 쌓이는 작업 디렉터리에
GPU 한 장당 약 40 GB가 있어야 한다. GPU 네 장이면 약 160 GB다.

인터넷 연결이 필요하다. 첫 빌드에서 NVIDIA의 Isaac Lab 기반 이미지를 내려받고, 실행
중에는 결과를 허깅페이스에 올린다.

## 3. `.env` 파일 만들기

설정은 전부 `.env`라는 파일 하나로 넣는다. 이미지 안에는 아무 설정도 굽지 않으므로,
토큰이 이미지에 남지 않는다.

```bash
cd /home/ubuntu/mimic_the_mimicgen/hf80k
cp .env.example .env
chmod 600 .env
```

`.env`를 열어 아래 두 줄만 채우면 된다. 나머지는 기본값이 들어 있고 그대로 두면 된다.

```
HF_TOKEN=hf_로 시작하는 본인의 쓰기 권한 토큰
HF_REPO_ID=본인계정/데이터셋이름
```

토큰은 허깅페이스 홈페이지의 Settings 안 Access Tokens에서 만든다. 권한은 쓰기(write)가
필요하다. 저장소는 미리 만들어 두지 않아도 된다. 없으면 파이프라인이 만든다. 기본값이
비공개이고, 공개로 올리려면 `.env`의 `HF_PRIVATE`를 `0`으로 바꾼다.

`.env`는 실행할 때만 컨테이너에 전달되고 이미지에는 들어가지 않는다. 코드 저장소에도
올라가지 않도록 제외해 두었다.

## 4. 실행 순서

네 줄이다. 전부 `hf80k` 폴더 안에서 실행한다.

```bash
cd /home/ubuntu/mimic_the_mimicgen/hf80k

make check        # 자산 세 개와 .env가 갖춰졌는지 본다. 몇 초
make build        # 도커 이미지를 굽는다. 처음에는 30분에서 40분
make smoke        # 100편만 만들어 전체 동작을 확인한다. 약 40분
make run-4gpu     # 본 실행. GPU 네 장에 2만 편씩 나눠 8만 편을 만든다
```

각 단계가 무엇을 하는지 아래에 적는다.

`make check`는 자산 세 개가 `assets/` 아래에 있는지, `.env`에 토큰과 저장소 이름이
채워졌는지 확인하고 하나씩 결과를 출력한다. 여기서 하나라도 없다고 나오면 다음 단계로
가지 않는다. `make build`도 시작할 때 이 검사를 먼저 한다.

`make build`는 이미지 이름을 `fr3-hf80k:latest`로 굽는다. 처음에는 NVIDIA의 Isaac Lab
기반 이미지 48.6 GB를 내려받아야 해서 오래 걸리고, 걸리는 시간은 회선 속도가 좌우한다.
두 번째부터는 바뀐 부분만 다시 굽기 때문에 1분 안에 끝난다.

`make smoke`는 100편을 만들어 다섯 단계가 전부 도는지 확인한다. 결과는 본 실행과 섞이지
않도록 `/data/hf80k/gpu0-smoke`에 따로 쌓인다. 끝까지 돌면 저장소에 데이터가 올라간 것을
직접 확인할 수 있다. 본 실행 전에 한 번 하기를 권한다. 설정이 잘못됐을 때 8만 편을 돌린
뒤가 아니라 40분 뒤에 알 수 있다.

`make run-4gpu`는 컨테이너 네 개를 백그라운드로 띄운다. GPU 한 장당 하나이고, 각각 2만
편을 맡는다. 컨테이너마다 작업 디렉터리와 난수 시드와 저장소 안 위치를 서로 다르게
자동으로 넣는다. 세 가지가 같으면 네 대가 서로의 결과를 덮어써서 8만 편이 아니라 2만
편만 남는데, 이 명령을 쓰면 그 일이 생기지 않는다.

GPU가 한 장이면 `make run-4gpu` 대신 `make run`을 쓴다. 이때는 `.env`의
`TARGET_EPISODES`가 만들 편수다.

## 5. 진행 상황 보기

```bash
make progress WORK='/data/hf80k/gpu*'   # 청크 몇 개가 끝났고 몇 편이 나왔는지 센다
make logs GPU=0                         # 0번 GPU 컨테이너의 로그를 따라간다
make state GPU=0                        # 지금 계획과 진행 상황을 본다
make stop GPU=0                         # 0번 컨테이너를 멈춘다
```

작업은 500편 단위로 끊어서 진행한다. 이 단위를 청크라고 부른다. 청크 하나가 끝날 때마다
그 청크의 결과가 바로 허깅페이스에 올라가고, 완료 표시 파일이 남는다. 그래서 중간에
멈추거나 기계가 재부팅돼도 `make run-4gpu`를 다시 실행하면 끝난 청크는 건너뛰고 이어서
한다. 처음부터 다시 하지 않는다.

## 6. 끝나면 하나로 합치기

본 실행이 전부 끝나면 마지막에 한 번 실행한다.

```bash
make aggregate WORK='/data/hf80k/gpu*'
```

네 대가 만든 결과를 하나의 데이터셋으로 합쳐 저장소 최상위에 올린다. 이 단계까지 마쳐야
학습 코드에서 `LeRobotDataset("본인계정/데이터셋이름")` 한 줄로 열린다.

작은따옴표 안의 `/data/hf80k/gpu*`를 반드시 그대로 넘겨야 한다. 하나만 넘기면 그 한
대분인 2만 편만 담긴 데이터셋이 오류 없이 만들어진다.

합친 편수가 청크 편수의 합과 다르면 오류를 내고 멈춘다. 일부만 담긴 데이터셋이 조용히
만들어지지 않게 하려는 것이다.

## 7. 걸리는 시간과 용량

아래는 L40S GPU 한 장으로 100편을 끝까지 돌려 실제로 잰 값이다.

| 단계 | 하는 일 | 편당 |
|---|---|---:|
| 생성 | 시연을 새 배치로 옮겨 궤적을 만들고 성공한 것만 남긴다 | 11.6초 |
| 변환 | 로봇 제어 명령 형식으로 바꾼다 | 1.4초 |
| 렌더 | 카메라 세 대로 320×180 크기의 영상을 찍는다 | 5.6초 |
| 기록 | LeRobot 데이터셋으로 쓰고 영상을 H.264로 압축한다 | 4.3초 |
| 업로드 | 허깅페이스에 올린다 | 0.07초 |
| 합계 | | 23.0초 |

여기서 8만 편을 계산하면 GPU 한 장에 21.3일, 네 장에 5.3일이다. 이 값은 100편 실행을
늘린 추정이다. 본 실행은 청크가 500편이라 시뮬레이터를 띄우는 비용이 편당 더 적게
들어가므로 이보다 조금 짧아진다.

성공률은 실행 전체로 보면 약 13%다. 100편을 만드는 데 시도가 722번 들었다. 청크 하나씩
떼어 보면 11%에서 19% 사이로 나온다. 실패한 시도는 저장하지 않으며, 위의 편당 시간에
이 실패분이 이미 포함돼 있다.

용량은 완성된 데이터 기준으로 편당 0.92 MB다. 8만 편이면 약 73 GB다. 만드는 도중에는
중간 파일이 쌓이는데, 청크 하나가 끝날 때마다 지우므로 작업 디렉터리에는 GPU 한 장당
약 40 GB가 있으면 된다.

## 8. 문제가 생겼을 때

**`make check`가 자산이 없다고 한다.** 1절의 `mv` 명령으로 옮긴 위치를 확인한다.
`hf80k/assets/` 아래에 `fwd_annotated.hdf5` 파일 하나와 `fr3_` 로 시작하는 폴더 두 개가
있어야 한다.

**빌드가 디스크 부족으로 멈춘다.** 도커가 이미지를 저장하는 곳의 여유를 본다.
`docker system df`로 확인하고 `docker system prune -a`로 쓰지 않는 이미지를 지운다.

**컨테이너가 시작하자마자 죽는다.** `make logs GPU=0`을 본다. 실행 전 검사가 열네 가지를
하나씩 확인하고 무엇이 통과하고 무엇이 실패했는지 출력한다. 토큰이 틀렸거나 GPU가 안
보이면 여기서 바로 잡힌다.

**청크 하나가 실패했다.** 로그에 실패한 단계와 원인이 남는다. 컨테이너는 그 청크를 두 번
다시 시도하고, 그래도 안 되면 다음 청크로 넘어간다. 이미 만들어 둔 산출물은 지우지 않고
실패한 단계부터 다시 하므로, 재시도가 앞 단계를 처음부터 반복하지는 않는다.

**허깅페이스 데이터 뷰어의 행 수가 터무니없이 작다.** 6절의 합치기를 아직 하지 않은
상태다. 합치기 전에는 저장소 최상위에 데이터셋이 없고, 그러면 뷰어가 저장소를 영상 폴더로
보고 영상 파일 개수를 행 수로 표시한다. 합치기를 마치면 프레임 수가 제대로 나온다.
100편을 올렸다면 17,700이다.

**중간에 멈추고 싶다.** `make stop GPU=0`으로 멈춘다. 나중에 `make run-4gpu`를 다시
실행하면 끝난 청크를 건너뛰고 이어서 한다.

## 9. 바꿔도 되는 값

`.env`에서 자주 건드리는 것만 적는다. 전체 목록과 뜻은 `.env.example`의 주석과
`INTERFACE.md`에 있다.

| 항목 | 기본값 | 뜻 |
|---|---|---|
| `TARGET_EPISODES` | 80000 | 컨테이너 한 대가 만들 편수. `make run-4gpu`는 2만으로 덮어쓴다 |
| `CHUNK_SIZE` | 500 | 몇 편마다 끊어서 올리고 완료 표시를 남길지 |
| `NUM_ENVS` | 16 | 시뮬레이터에서 동시에 돌리는 장면 수. 4로 낮추면 생성이 약 2배 느려진다 |
| `RENDER_PROCS` | 2 | 영상을 찍는 프로세스 수. GPU 메모리가 모자라면 1로 낮춘다 |
| `IMAGE_WIDTH`, `IMAGE_HEIGHT` | 320, 180 | 영상 크기. 키우면 시간과 용량이 함께 늘어난다 |
| `HF_PRIVATE` | 1 | 1이면 비공개 저장소로 만든다 |
| `UPLOAD_EACH_CHUNK` | 1 | 1이면 청크마다 바로 올린다. 0이면 마지막 합치기에서 한 번에 올린다 |

명령줄에서 한 번만 다르게 주고 싶으면 `make` 뒤에 붙인다. 예를 들어 연습 실행을 20편으로
줄이려면 `make smoke TARGET=20 CHUNK=10`이라고 한다.
