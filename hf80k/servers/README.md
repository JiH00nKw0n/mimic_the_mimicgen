# 서버별 실행 설정

hf80k 파이프라인을 실제로 돌리는 기계마다 무엇이 어디에 있고 어떤 제약이 있는지 적어
둔 폴더다. 기계마다 에셋 경로, 작업 폴더, 캐시 위치, 쓸 수 있는 컨테이너 이미지가 다르다.
그 차이를 기억에 두면 매번 `docker run` 줄을 손으로 다시 쓰게 되고, 한 군데를 빼먹으면
컨테이너가 뜨고 나서야 알게 된다.

주소와 계정 이름과 키 파일 이름은 여기에 적지 않는다. 이 저장소가 공개라서다. 접속은
각자의 `~/.ssh/config`에 적어 둔 별칭으로 한다. 아래 문서는 그 별칭만 쓴다.

| 문서 | 어떤 기계이고 무엇을 조심해야 하나 |
|---|---|
| `hf80k/servers/isaac_pro6000.md` | 연구실 RTX PRO 6000 네 장 서버. 지워지는 디스크가 없어 작업물을 두어도 되지만, GPU 예약이 장부로 돌고 공용 이미지로는 우리 기어 태스크가 뜨지 않는다 |
| `hf80k/servers/aws_l40s.md` | AWS L40S 한 장 인스턴스. 빠르지만 `/opt/dlami/nvme`가 인스턴스를 멈출 때 지워지므로 작업물을 두면 잃는다 |
| `hf80k/servers/run_gear.sh` | 두 기계 어디서나 기어 조립 파이프라인이나 진단 도구 하나를 같은 방식으로 띄우는 스크립트. 기계 이름만 바꿔 쓴다 |

## 두 기계에 공통인 것

컨테이너 안의 경로는 어느 기계에서든 같다. 바깥에서 무엇을 어디에 붙이는지만 다르다.

| 컨테이너 안 경로 | 무엇이 들어오나 |
|---|---|
| `/opt/hf80k/assets` | 기어와 받침 에셋, 그리고 생성이 소스로 읽는 시연 파일 `multigear_annotated.hdf5` |
| `/opt/hf80k/src` | 이 저장소의 `hf80k/src`. 읽기 전용으로 붙여서 이미지를 다시 굽지 않고 코드를 고친다 |
| `/opt/hf80k/tools` | 이 저장소의 `hf80k/tools`. 진단 도구가 여기 있다 |
| `/work` | 실행마다 따로 두는 작업 폴더. `.env`, `chunks/`, `logs/`, `state.json`이 여기 생긴다 |
| `/isaac-sim/kit/cache`와 `/root/.cache/ov` | Kit 셰이더와 에셋 캐시. 실행끼리 나눠 써도 되고, 나눠 쓰면 시작이 몇 분 빨라진다 |

허깅페이스 쓰기 토큰은 서버의 작업 폴더에 둔 `.env`에만 넣는다. 이미지에 굽지 않고
저장소에 넣지 않는다. 그 파일은 `chmod 600`으로 둔다.
